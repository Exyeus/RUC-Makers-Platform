# 参赛工作台 UI 重构

## 需求与范围

主任务卡：按用户提供的 `ruc-ui-redesign-kit.zip`（2026-11-07）完成参赛首页及各工作区页面的统一重构。设计包的提示词、CSS 与 HTML 是视觉与验收依据；其中的示例日期、人数与 Profile 位置不作为业务数据。

- **做什么**：让选手在首页看到当前任务、作品截止时间、自己的作品记录和帮助入口。
- **需求链接**：本文件记录可公开的需求；原设计包位于本地忽略目录 `tmp/ruc-ui-redesign-kit.zip`。
- **负责人输入**：用户提供设计包与开发/PR 授权；实现与验证由本次 coding agent 完成；独立 reviewer 只读复看。
- **正确例子**：见下表。视觉使用设计包的深色、紫色、16–18px 正文、两列工作区与窄屏重排；不缩放整个页面。
- **演示时间**：本次 PR 可供走查，真实 Windows/Edge 和用户任务验收待安排。
- **进展 / PR**：已定需求，开发与本机验证完成后通过 `feat/refactor-ui-workbench` 面向 `main` 提交。

登录首页提供任务面板，活动日程、通知公告、学习与指南、组队、作品、帮助及角色工作台共用同一套导航、字体、配色与控件。继续复用 Django 模板、原生 SVG、现有 Profile、角色工作台、抽屉焦点管理与服务端权限。访客宣传页和独立登录/找回密码页面保留入口布局；公开访问的工作区页面也使用统一主题。路演全屏模式保留隐藏导航和全屏计时布局。无需模型、迁移、额外前端依赖或业务配置。

## 状态与正确例子

| 输入状态 | 首页主任务 / 结果 |
| --- | --- |
| 未报名且报名开放 | 填写参赛信息 |
| 未报名且报名已截止 | 咨询参赛资格 / 支持 |
| 已报名、未组队 | 寻找或创建队伍；名单冻结后转支持 |
| 已组队、必读未完成 | 打开本人的第一篇未读必读；作品入口仍可用 |
| 无必读或全部已读、作品未提交 | 准备作品材料 |
| 排队上传（含曾正式提交后再次排队） | 查看上传与回执，不宣称已正式提交 |
| 需要补充 | 查看检查意见与当前可执行操作 |
| 已正式提交或通过检查 | 核对提交回执；编辑资格以作品页状态为准 |
| 作品截止后 | 查看已有提交记录；无正式提交记录时联系支持 |
| 成绩已公布 | 查看结果；保留作品记录入口 |
| 无通知 / 无后续日程 / 无资源 | 显示对应空状态，不编造通知或安排 |
| 长标题或含 HTML 的名称 | 自动换行、模板转义，无可执行 HTML |

两处作品截止显示共用模板与同一个服务端时间，使用活动时区。准备进度只作推荐，不改变报名、组队、阅读、上传或提交规则。不增加个人账户入口，不复制读过文章或提交记录。

## 验证与限制

定向 Django 测试在全新的临时 PostgreSQL 实例执行，覆盖上述状态、跨活动阅读隔离、路演/评分锁定文案、原入口、CSRF 流程、跨页主题与导航高亮、详情页导航归属、主办方页面和路演全屏模式。仓库检查入口为 `tools/check-activity.sh`；实际通过数量与远端 Activity CI 结果记录在 PR 中。

使用真实 Django 响应和本地资源进行 Chromium 浏览器检查：2560、1920、1440、1280、1024、768、390、320 CSS px；检查横向溢出、主任务/截止/作品首屏可见、抽屉打开与焦点循环、Esc 返回、焦点轮廓、减少动态偏好。另检查根字号放大到 200% 和脚本加载失败时仍显示服务端任务内容。浏览器检查使用合成测试数据，截图保留在忽略目录。跨页检查另覆盖日程、公告、资料详情、队伍/个人资料表单、作品、支持、后台列表与路演全屏，核对页面背景、控件、移动端重排和横向溢出。

这些检查不能代替真实 Windows 150% / Edge 100%、浏览器 200% 缩放、完整无障碍审计或独立用户的 5 秒/30 秒任务走查；以上仍需人工验收。首页使用服务端渲染，无异步数据载入或假保存反馈；数据库/服务故障仍按现有服务端错误处理流程处理。

独立审计记录保留在本地忽略目录 `tmp/audit-refactor-ui-workbench.md`，PR 引用结论和验证范围，不提交本机运行数据或原有其他工作。

## 按界面标注精简

工作区移除顶部面包屑、侧栏活动切换卡及首页标题下的标语；导航分为参赛工作台、活动安排、学习与展示、帮助与入口。侧栏、首页材料区和手机底栏移除加分入口，手机常用入口改为日程。通知和退出使用无边框图标，退出保留 POST/CSRF、可访问名称及悬停文字。页面与侧栏使用深色细滚动条；强制配色模式交回系统绘制。工作区品牌标签使用 HACKATHON。

## 展开的组队筛选

“我的队伍与组队”页把筛选放在栏目导航之后，先展示完整选项，再展示队伍、公开找队友的伙伴及交流内容。内容形式、队伍赛道和伙伴关键词均为直接可见的标签式单选；关键词按九个既有分类排列，不折叠、不使用下拉菜单。桌面三列分类卡片，平板两列，手机单列换行。

搜索与三组筛选共用一个 GET 表单，顶部“查看结果”和底部“应用筛选”均提交全部状态，“清除筛选”回到无条件页面。关键词用于公开伙伴，赛道用于队伍，内容形式用于交流卡片；查询和权限继续沿用现有规则。通过链接传入的自定义关键词显示在独立分类中，并保留选中状态。页面在禁用脚本时仍能选择和筛选，单选使用原生键盘和辅助技术语义。

## 组队信息展示与发布示例

“还在寻找队伍的伙伴”“交流与共创”“作品池”各有独立展示面板和醒目的发布按钮。真实信息使用三列卡片排列，平板两列、手机单列；没有内容或筛选无匹配时保留说明和发布入口。

每个区域另有三个默认展开、可收起的“写法示例”，展示个人介绍、经历、开放问题、求助、灵感、作品日志和微型共创的写法，并说明如何邀请伙伴参与。示例是页面指导，不创建选手、队伍或帖子，不计入筛选结果。点击内容示例仅为新表单选好内容形式，正文留给选手填写；服务端继续验证提交，编辑已有卡片不受 URL 中的类型影响。

示例采用紧凑的分类卡片，标题、技能、正文和合作期待分层展示，发布动作为整行按钮。“怎么写”与个人公开设置默认收起，可用键盘或触控展开，避免说明文字挤占卡片。栏目标题保留独立图标和主发布按钮。

工作区共用的五份 CSS URL 使用文件内容摘要作为版本参数；文件内容更新后，普通刷新会请求新 URL。摘要按文件修改时间与大小缓存，不需要手工改版本号，也不修改全站静态存储后端。测试同时检查旧 CSS 缓存与新模板组合，以及同一浏览器加载带新版本 URL 后的布局。

“更新我的介绍”打开参赛资料，填写一句话介绍、技能与项目想法。普通模式需主动勾选公开展示且尚未入队；启用匹配后另需在“匹配资料”同意匹配、选择“本活动可见”。帖子选择公开后显示在广场，取消公开保存为草稿。作品池收录公开的灵感、展示 / 开发日志和微型共创；正式参赛材料仍从“我的作品”提交。

## 黑客松关键词整改

活动界面统一使用“黑客松 / HACKATHON”，包括访客与登录入口、浏览器标题、选手入口说明、通用表单、组队详情、匹配表单/未开放状态/撮合后台，以及现存加分页面。找回密码邮件与新审核日志也采用黑客松名称。初始化不再把指南中的“黑客松”改写成旧品牌。
