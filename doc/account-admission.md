## 注册与登录

登录和注册共用学号/邮箱识别。学号注册必须填邮箱；邮箱注册后在“账号与订阅”绑定学号。两个标识对应同一账号、同一密码。注册不会授予主办方、评委或参赛权限。原有账号和密码保留，旧账号需登录后补验证邮箱。账号邮箱只有完成链接中的确认 POST 后才标记已验证。

找回密码支持学号或邮箱，只发往已验证地址，统一反馈、限频、30 分钟有效、单次使用。令牌摘要存储，绑定签发时认证状态。改密后旧会话、待更换邮箱、全部账号操作令牌和旧密码找回令牌失效。更换邮箱需当前密码，新邮箱验证前原邮箱有效。忘记密码且没有已验证邮箱的旧账号须由组委会核验原报名联系方式后人工处理。

## 通过名单

主办方总控页进入“通过名单与准入”，也可访问 `/hackathon/<slug>/manage/admission/`。CSV 为 UTF-8，字段 `student_id,email,approved`；前两列必需，approved 可省略且默认为 true。学号按字符串保存；一份文件内学号、非空邮箱不能重复。

先上传预览，再在当前会话确认导入。只更新所列学号，不删除其他名单；false 表示撤销资格。新增通过记录必须有原报名邮箱。补录/更正也可在同页单条完成。人工指定账号必须已绑定同一学号，操作者需先核对原报名手机号、微信等依据并填写原因；系统不声称已完成短信认证。不会自动合并或转移已有账号。

准入条件：账号正常且邮箱已验证；绑定的学号属于本届有效通过记录；账号邮箱与原报名邮箱一致，或组委会已人工核验指定该账号。检查每次请求执行，旧 Participant.admission_state 不授予访问资格。公开宣传页、账号设置、验证/找回、退订可以使用，其他活动页面、接口、下载、上传均受门禁保护。工作人员沿用原角色权限，播放助手沿用主办方签发的短期活动令牌。

`Hackathon.admission_required` 控制各活动独立启用。香港当前活动启用；未形成名单时普通用户默认拒绝。撤销资格无需等待会话过期。组队、名单确认和作品提交也检查队员资格。

## 邮件订阅

活动动态和后续活动信息是两项独立、自愿、默认关闭的偏好，与是否入选无关。邮箱完成验证且账号正常后才有资格接收推送。退订链接使用独立的账号级入口，即使原活动私有化也仍可使用；GET 只确认、POST 才修改，不影响安全邮件。

管理命令默认只预览人数，不输出收件地址、不发送邮件：

```bash
python manage.py send_hackathon_update --hackathon tongzhou26 --audience future --campaign next-event-001 --subject '后续活动信息' --body-file /private/message.txt
```

由操作者明确追加 `--send` 才逐人投递，正文自动带退订链接。`activity` 对应活动动态，`future` 对应后续活动。相同活动与 campaign 跳过已记录成功的投递；SMTP 接受后进程崩溃仍可能存在无法严格去重的窗口，不能承诺 exactly-once。本次部署不执行群发。

## 部署与恢复

新增迁移 0020/0021 只扩展 schema，不回填旧验证状态、不改写用户/报名/队伍/作品。上线前保留数据库和受影响源文件快照；对照原文件哈希拒绝覆盖同期变更。回退优先恢复代码和活动开关并保留新增表，不能用旧数据库覆盖上线后的新账号与数据。真实名单、邮箱、数据库备份和配置均不入仓库。
