## 实现

- `entry_base.html` 复用原粒子场景、入口版式、活动信息和导航。首页、学号登录/注册、主办方/邮箱及评委登录共用入口。
- `brand.css` 为活动公共模板、工作台、手机导航、表单、错误状态和评委评分菜单提供同一套深色主题。
- 使用官方蓝紫渐变创协 Logo 替代主标志；页脚保留 Eventyay 引擎署名；宣传背景及“造物有心”标识来自知识库原图。素材路径和来源见 `app/eventyay/static/hackathon/brand/SOURCES.md`。
- 默认 POST 登出返回当前活动主页；显式账号切换的 `next`、POST/CSRF、SSO cookie 清理、安全重定向和登录角色分流保持。

## 验证与边界

- 平台：167 Linux，同一源码树，独立 PostgreSQL Unix socket、独立库和临时媒体目录。没有对现有活动数据库执行迁移、初始化或测试写入。
- Django check 和 Ruff 通过；check 保留隔离环境没有 Celery worker 的既有警告。
- 全量活动测试第二轮 264 passed、2 failed、4 subtests passed。两项失败分别是旧测试禁止已授权加入的品牌 alt 文本，以及隔离测试设置自定义 CSRF cookie 名。更新品牌断言、恢复标准 Cookie 名后，账号、上传、登录导航、入口及评委相关 86 项定向测试全部通过；未将这次定向复验描述为又跑了一遍完整套件。
- 12 类页面：入口、登录、注册、主办方、评委入口、选手工作台、个人资料、日程、组队、指南、评分、管理。Chromium 对修改前 390/1440px 和修改后 320/390/768/1024/1440/1920px 共 96 组页面检查通过；有同尺寸前后截图。
- 浏览器走通桌面/手机错误密码 → 正确登录 → POST 登出 → 首页；学号转主办方账户切换；邮箱页转学号入口；无 JS 降级；无页面 JS 异常和横向溢出。
