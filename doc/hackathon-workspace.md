# 创客营一体化工作台

工作台直接运行在 Eventyay 的 Django 应用中，使用现有账户、活动、PostgreSQL 和会话系统。入口为 `/hackathon/`。存在公开且尚未结束的创客营时，网站首页会进入最近一届的工作台，现有活动列表、票务和会议功能仍可通过原路由访问。

## 初始化创客营

初始化、迁移和公开活动是独立操作。`start-local.sh` 只检查迁移状态，不自动迁移、创建或公开工作区。先确认当前配置连接的是开发数据库，再执行下列命令。

升级到 `0012_isolate_existing_hackathons` 会将升级前所有工作区标为黑客松板块；目前该板块的参与者与管理入口均返回 404。升级前应备份并确认旧活动的访问安排；初始化新的创客营不会复制旧活动数据。

在 `app/` 目录、已配置好项目数据库与 Redis 的环境执行：

```bash
.venv/bin/python manage.py migrate
.venv/bin/python manage.py setup_hackathon \
  --organizer hackathon \
  --event maker-camp \
  --slug camp \
  --name '人大创客营' --program maker_camp \
  --start-date 2026-10-21 \
  --publish
```

日期仅作命令示例，替换为正式日期。省略 `--start-date` 会生成 30 天后的筹备排期；省略 `--publish` 会保持活动私有。命令可绑定已有 Eventyay 活动，也可创建新的活动；同一工作台已存在时不覆盖其数据。每届使用不同 `--event` 和 `--slug`。初始内容含 8 篇可编辑指南、2 条示例赛道、2 天的筹备日程与明确标注待确认的公告，不生成虚假参赛人数、作品或成绩。

已有 Eventyay 实例管理员可以进入 `/hackathon/camp/manage/`。非实例管理员必须属于该活动主办方的管理团队，拥有 `can_change_event_settings` 且有该活动的访问权限。普通 `is_staff` 标记不授予活动管理权限。全新安装可使用项目原有的 `manage.py create_admin_user` 设置管理员。

从旧活动切换到创客营时，原来只被授权管理旧活动的团队不会自动获得新活动权限。需要沿用同一主办方的管理团队时，可显式复制其活动访问授权：

```bash
.venv/bin/python manage.py setup_hackathon --slug camp --copy-organizers-from next
```

将 `next` 替换为来源工作区标识。此选项也可在首次初始化时传入，或对已有创客营重复执行；已有内容不会被覆盖。只为同一主办方下拥有来源活动访问权和 `can_change_event_settings` 的管理团队添加目标活动访问权，不复制选手、评委或志愿者角色，不修改实例管理员权限或 `all_events`。

主办方使用 `/hackathon/camp/account/organizer/` 登录，验证成功后进入活动管理。登录后各页面右上角保留“主办方后台”入口，手机上显示为设置图标按钮；侧栏和手机底部导航也保留管理菜单。原来的 `/login/?next=/hackathon/camp/manage/` 链接也会转到此入口。学号登录和邮箱登录页面可以互相切换；所有登录后的页面右上角都有“退出登录”，手机端同样显示。退出后回到创客营登录页，清除当前会话；切换主办方账户时可使用“退出并切换账户”。

开发运行沿用 Eventyay 配置。部署时使用现有静态文件构建与收集流程；新增资源位于 `eventyay/static/hackathon/`，无需新增前端构建工具。临时预览可使用：

```bash
.venv/bin/python manage.py runserver
```

从另一台电脑预览时，`localhost` 指向访问者自己的电脑。请使用开发机的局域网 IP，并将 `EVY_SITE_URL` 配成相同地址，否则站点的域名校验会返回 400。以下是当前开发机的启动示例（在 `app/` 下执行，需本机 PostgreSQL 和 Redis 已运行）：

```bash
EVY_POSTGRES_HOST=127.0.0.1 EVY_POSTGRES_PORT=55432 \
EVY_POSTGRES_USER=tianjiaming EVY_POSTGRES_DB=eventyay-db \
EVY_SITE_URL=http://10.77.110.167:8000 \
EVY_SHORT_URL=http://10.77.110.167:8000 \
EVY_TALK_HOSTNAME=http://10.77.110.167:8000 EVY_DEBUG=false \
.venv/bin/python manage.py run_hackathon_preview 0.0.0.0:8000 --insecure
```

浏览器打开 `http://10.77.110.167:8000/hackathon/camp/`；开发机 IP 变化时同步替换启动配置和访问地址。`--insecure` 仅用于本地预览的静态资源服务，正式部署使用现有部署流程。

正式发布前，在“活动设置”确认活动起止时间、场地、组委会联系方式、队伍人数、所有截止时间和路演时长，在“内容管理”确认日程、赛道、指南与公告。活动起止时间与各日程条目单独维护；改变日期后也应核对日程。日期输入与显示均使用关联 Eventyay 活动的时区。

## 创客营板块与交流

当前只开放 `program=maker_camp` 的创客营。迁移 `0012` 将升级前的工作区保留为黑客松业务，原数据不删除；这些工作区不出现在活动入口、首页推荐或历届展厅中，直接访问其页面、API 与现场令牌接口均返回 404。新建创客营使用上方命令，默认标识为 `camp`；`--program hackathon` 只创建暂不可访问的黑客松工作区。

个人资料入口位于右上角头像，通知入口位于铃铛（包含手机端）。首页小时日历每格代表一小时，活动与重要截止分别着色，悬停、键盘聚焦或点按可查看该小时全部安排；数据来自活动截止时间与主办方维护的日程。

组队广场整合交流与共创、作品池、找队友，以及启用匹配后的推荐和名单确认。支持灵感、经历/痛点、开放问题、展示/开发日志、求助、微型共创和招募七类卡片，卡片可附作品、图片或录屏链接，并注明希望怎样回应。作者可关闭回应或保存为非公开草稿；回应默认私密，仅发布者、回应者与主办方可见。发布、回应不自动获得录取加分。

个人资料和匹配资料提供活动前两天的小时格子，桌面可拖动连续圈选，触屏和键盘可逐格勾选。只有活动起止时间内的完整小时可选。具体缺席时段不公开；匹配页明确确认安排后，将剩余小时换算为现有匹配引擎的半小时时段。已确认匹配时间的参与者更新报名时段时，会同步匹配时间并使旧推荐失效。

加分规则由主办方在“内容管理 → 加分规则”配置事项、分值、证明标准并公布。参与者每个事项限申请一次，主办方在“加分规则”页面填写审核说明并通过或拒绝。通过时记录当时分值；重复请求和后续规则改分不会重复计分。创客营参与加分独立于作品评审分数。未配置时展示“待公布”，不预设未经确认的分值。Token Panel 保持待定。

## 手机与平板访问

使用同一个网址，页面按屏幕宽度自动适配，无需安装或切换版本。手机采用单列卡片和按身份显示的底部常用导航，完整功能位于“更多”或左上角菜单；主办方名单、作品检查、路演队列和成绩表在手机上逐条展示全部字段，原有签到、审核、调度和评分按钮仍可操作。平板采用可展开导航和多列布局，评分时可并排阅读作品材料与填写分数。

触屏布局增加按钮点击区域和输入字号，适配横竖屏以及屏幕安全区域。菜单支持点击遮罩、关闭按钮或 Escape 关闭，并将键盘焦点限制在展开的菜单中。桌面、手机、平板共用账户、数据和原有业务流程。

### 学号账户与个人资料

选手从 `/hackathon/camp/account/signup/` 注册，填写学号、姓名和本站密码，不需要邮箱。学号支持 4–32 位数字或英文字母，统一转为大写，在本网站全局唯一；前导零保留。学号和原有 Eventyay 用户一对一关联，存入 PostgreSQL，密码使用现有密码哈希机制。数据库唯一约束防止并发重复注册；登录按学号和来源 IP 限制尝试次数，保留原有账户停用及双因素验证逻辑。原邮箱账户仍可使用原登录入口。

学号是本站登录标识，尚未对接校园统一身份认证，不代表已经核验在校身份。多学校联合举办时需要先约定学号命名规则，避免不同学校同号。无邮箱账户无法使用邮件找回密码，由管理员核验后运行 `.venv/bin/python manage.py reset_student_password <学号>`，在终端隐藏输入新密码；原登录会话随之失效。主办方在名单中可查看、搜索和导出学号，公众看不到学号或联系方式。

点击右上角头像进入个人资料，可按开发、AI、设计、研究、硬件、关注的问题、兴趣、性格和协作期待添加标签，数量不限，也可自定义标签（每个最多 40 字）。还可填写 120 字以内的一句话介绍，并保留详细技能与项目想法。只有主动开启公开展示且尚未入队的选手会出现在组队广场。广场支持关键词筛选，并搜索姓名、介绍和技能。

### 作品提交

1. 队长保存草稿，获得作品编号。
2. 上传电子海报（PNG/JPG/WebP，最大 20 MiB），可选文稿（PDF/PPTX）、录屏（MP4/WebM）和附件（ZIP/PDF，分别最大 512 MiB）。项目卡必须是电子海报，不能用立牌照片替代；该内容质量由工作人员人工检查。
3. 提供代码仓库、已实现功能说明、Demo 或录屏、备用链接或录屏、实机演示步骤，完成自查。
4. 点击“正式提交”，确认状态和首次提交时间。单独上传不等于正式提交；后续替换附件会重新进入待补充状态，需再次提交和检查。

提交采用版本号防止旧页面覆盖新内容。同一版本、相同内容和操作的紧邻重试不增加版本号。上传检查文件类型、大小、基本格式、图片有效性、ZIP 路径和解压体积；压缩包最多 20,000 个条目，目录元数据不超过 4 MiB，声明解压大小不超过 2 GiB；不接受分卷 / ZIP64 归档。附件存放在 `DATA_DIR/hackathon-private/`，不提供直接媒体 URL，只通过检查权限的下载视图读取。请确保 Web 服务器没有把整个 `DATA_DIR` 作为公开目录，并将该目录纳入备份。公开展厅只可读取授权作品的海报，不公开文稿、录像和源代码附件。其他链接由队伍主动授权公开。

### 大文件传输与存储

浏览器先登记上传意图，再在 Web Worker 中分段计算 SHA-256，以 8 MiB 分块上传，不把整个文件放进内存。服务端写入私有临时目录，每块完成 `fsync` 后才更新 PostgreSQL 中的接收偏移量。任务允许暂停、自动重试和刷新后重新选择原文件续传；保留至登记后 24 小时或材料冻结时间，以较早者为准。完整文件再次计算 SHA-256，与浏览器指纹匹配后才归档。正式提交允许登记等待尚未完成的上传，详见下文“截止前排队提交与凭证”。

同一作品同类材料仅允许一个进行中的任务。重复启动同一文件返回已有任务，重复分块比对内容，乱序或冲突返回 409。完成请求可重复调用，重复文件不反复增加作品版本号。新材料写入并校验成功前保留旧材料；替换提交后才删除旧文件。进程在分块写入与数据库提交之间退出时，下次请求按数据库确认的偏移量截断未确认尾部。硬链接发布到最终目录，避免额外复制整个文件；临时目录和最终目录必须位于同一个支持硬链接的文件系统。

存储路径按 `活动 ID / 队伍 UUID / 作品 UUID / 材料类型 / 唯一文件名` 分层。下载名称自动生成 `队伍编号_作品编号_材料类型_校验摘要.扩展名`，数据库和作品页保留原文件名。每类材料保留当前有效版本，操作日志保留更换记录。下载支持 `Range`、`If-Range`、`ETag` 与 `HEAD`；Django 在 WSGI/ASGI 下都使用分块读取，供断点下载及录屏拖动使用。ASGI 下采用异步迭代器，避免同步文件响应被整体读取（参见 [Django 流式响应说明](https://docs.djangoproject.com/en/6.0/ref/request-response/#streaminghttpresponse)）。

仓库 Nginx 示例的 `client_max_body_size 10m` 足以承载默认 8 MiB 分块；保留此限制即可使用网页大文件上传。建议代理读取超时至少 120 秒，给最终校验留出时间。禁用 JavaScript 的普通表单上传及主办方补录仍使用整个 multipart 请求；如需让这些入口也接收 512 MiB，可仅对对应上传路由设置 `client_max_body_size 520m`，并确保代理/Django 临时目录有足够磁盘空间。正式环境应使用 HTTPS、持久磁盘与 PostgreSQL/文件联合备份；多应用实例必须共享同一私有文件目录。文件内容不存入数据库，不支持仅靠临时容器磁盘部署。

建议每小时运行以下命令，过期任务将取消，48 小时以上未被引用的残留文件会清理，上传凭证随活动保留。先使用 `--dry-run` 查看候选文件（命令使用与服务相同的数据库和 `DATA_DIR` 配置）：

```bash
.venv/bin/python manage.py cleanup_hackathon_uploads --dry-run
.venv/bin/python manage.py cleanup_hackathon_uploads
```

启动新任务时检查可用磁盘与当前活动已预留的上传体积，磁盘写入失败返回可重试错误，不覆盖旧材料。实际并发能力仍取决于磁盘、带宽与服务进程配置；活动前应按预计队伍数进行压测。

本地预览使用上面的 `run_hackathon_preview` 命令，使普通 HTTP 请求使用 WSGI，并正确提供开发静态资源。当前 Daphne 开发服务的输出缓冲在大文件下载时可能显著增加内存，即使应用本身逐块读取；正式 Docker 配置已将普通 HTTP 交给 Gunicorn WSGI，WebSocket 单独交给 Daphne。

建议提交时间用于留出检查窗口；最终提交截止后选手不能新建上传或修改作品文字，截止前已登记的上传可以在凭证期限内续传。主办方可从作品检查或选手名单进入异常补录，必须填写原因与发生时间，系统记录操作人、版本和原因。材料冻结后拒绝补录。已经开始/完成路演或已有确认评分的作品不能修改参评版本。

### 路演与评分

审核通过的作品可加入路演队列，重复生成不会重复排队。通过设备演练后才能标为就绪；同一时间仅一队处于展示中。暂停、继续与开始时间都保存在服务器，刷新页面不会重置。默认 120 秒展示、30 秒评分换场，页面每 2 秒同步；断网时明确标记失联，避免显示过期倒计时。下一队、后两队分别显示候场与准备提示。顺延记录原因，不删除队伍展示机会。

评委从 `/hackathon/camp/account/judge/` 登录，进入“现场打分”（`/hackathon/camp/judging/live/`）。主办方在路演调度点击“开始展示”后，评委页面每 3 秒同步当前队伍；等待页会自动打开该队的评分表。评分页同时展示海报、完整作品描述、体验步骤、代码及演示链接和附件。可通过队伍选择器、上一队/下一队或“全部队伍与评分”回看；回看模式不会自动跳走，点击“返回当前路演”恢复跟随。

开始输入后暂停自动跟随，换队时显示提示。评分请求始终绑定当前表单的作品，不会错记到新的路演队伍；保存后自动回到当前路演。未保存离开页面会提示确认。草稿可先保存再浏览其他页面，确认后才计入统计；重复或过期表单会提示重新核对，不覆盖其他页面已保存的新分数。断网时保留本页输入并重试现场同步，服务端成功响应才算保存完成。

主办方从“算分规则”（`/hackathon/camp/manage/scoring/`）配置四项权重，总和须为 100%；每项仍为 0–10 整数分。默认创新性/完成度与实机演示/实际价值/表达为 30/40/20/10，所有有效评委的加权总分取平均。支持各去掉 1–5 个最高和最低评委总分后求平均，不逐项去极值；相同分数也只删除指定份数。计算使用十进制数，最终四舍五入保留两位小数。人数不足时不生成最终分或名次、不允许公布；提名保留全部有效评委的意见。成绩页和 CSV 显示规则、采用评分数及去极值份数。

开始保存任何评分（包括草稿）或公布成绩后，算分规则锁定；事前可一键恢复默认规则。修改规则会使旧评分表失效，需重新打开核对。停用、标为垃圾账户、移除角色和队伍成员自己的评分不进入统计。每位评委每个特别奖最多确认提名 3 项；系统自动排除本人所属队伍。非本人队伍的其他利益冲突需主办方事先调整评委安排。统计显示已评/应评数量，缺评作品不进入正式排名，同分并列。成绩默认私有；全部有效评委完成后才能公布。公布后关闭评分变更，选手能看到改进建议。

## 现场本地播放助手

浏览器不能直接控制现场电脑的原生 PPT 进程，因此提供独立助手 `eventyay.hackathon.companion`。助手使用 Python 标准库，文稿播放需要现场安装 LibreOffice。它只控制自己启动的独立 LibreOffice 实例，不关闭其他办公进程。

1. 在路演调度生成 12 小时令牌。令牌只显示一次，数据库只保存哈希；生成新令牌会撤销旧令牌，也可主动撤销。角色权限和令牌过期均由服务器检查。
2. 在现场电脑执行，按提示粘贴令牌；不要把令牌放进 URL 或共享文档：

```bash
python -m eventyay.hackathon.companion \
  --url https://your-site.example/hackathon/camp/station/state/ \
  --cache ./stage-cache
```

3. 默认只进行演练与材料缓存。确认现场播放效果后添加 `--execute`；可用 `--office /path/to/soffice` 指定 LibreOffice。使用 `--unpack` 可安全解压 ZIP 附件，助手不会执行附件中的脚本。
4. 在无队伍展示时预下载队列材料，校验大小和 SHA-256，避免现场临时下载。开始展示时打开该队文稿，展示到点自动结束由助手启动的进程；结束本队或关闭助手也会清理该进程。暂停状态不会继续消耗展示时间。
5. 主办方另开路演大屏展示倒计时。网页 Demo 与备用录屏由现场技术人员使用缓存或链接切换；当前助手不自动登录网站、不启动项目源码、不保证不同办公软件的排版一致。

助手拒绝携带令牌跟随重定向或访问其他域；非本机地址要求 HTTPS。本地 HTTP 仅允许回环地址。断线保留到点结束保障，持续失联时关闭自己启动的播放进程。请提前验证专用电脑、视频声音、翻页笔、转接头、网络与备用方案；这里没有自动化的校内算力供应或远程桌面控制。

## 验证

测试位于 `app/tests/hackathon/`，覆盖页面、身份权限、多活动隔离、报名去重、队伍上限、冻结规则、真实提交与附件读取、文件伪装、版本冲突、评分权重/限额/回避、路演状态、志愿任务、工单隐私、CSV 公式转义和助手解压路径安全。

使用项目已有测试配置。该仓库默认在本地跳过迁移，但现有搜索索引依赖 PostgreSQL `pg_trgm` 扩展；从空测试数据库验证时应运行真实迁移：

```bash
GITHUB_WORKFLOW=local-hackathon-validation .venv/bin/pytest tests/hackathon --reuse-db
.venv/bin/python manage.py check
.venv/bin/python manage.py makemigrations --check --dry-run hackathon
.venv/bin/ruff check eventyay/hackathon tests/hackathon
```

新增功能验证可另运行 `node tests/hackathon/test_upload_hash.mjs`，将浏览器增量 SHA-256 与 Node 原生实现交叉比较。当前回归测试覆盖学号注册与登录、密码重置、资料关键词、上传重试与并发、校验失败保护、范围下载及原有黑客松流程。

本地实际浏览器验收已完成 320 MiB 文件的暂停、刷新续传、正式提交和完整下载校验。使用 WSGI 预览命令，本机测试包括两次浏览器校验与暂停约 30 秒，完整下载约 2 秒，服务进程 RSS 从约 540 MiB 增至 552 MiB（增加约 12 MiB）。这是本机单用户测试结果，不代表公网吞吐或多人并发上限。

本地人工验收至少走一次：报名 → 创建与加入队伍 → 草稿 → 海报上传 → 正式提交 → 审核与设备确认 → 候场/展示/换场 → 评委确认 → 公布结果 → 查看反馈。再用手机检查导航、表单、材料列表与候场状态。生产使用仍需配置并验证 HTTPS、数据库及私有文件备份、存储容量和现场负载。

## 截止前排队提交与凭证

大文件上传先登记一个小请求，再在浏览器计算 SHA-256 并绑定到该上传任务，最后按 8 MiB 分片传输。凭证记录服务器登记时间、本机点击时间、文件名、大小、哈希与哈希绑定时间，可在「我的作品」查询并下载带服务器签名的 JSON。只有服务器已确认的登记才允许续传；本机时间不能用来绕过截止。若哈希在截止后才绑定，凭证只能证明截止前登记了文件信息，不能证明该内容在截止前已固定。

截止前登记的任务可持续至登记后 24 小时或活动的材料最终冻结时间，以较早者为准。续传不会延长此期限；截止后不能创建新任务。已经开始路演或确认评分的作品仍不能替换材料。

每个活动默认开放 4 个上传通道（`constants.py` 的 `UPLOAD_SLOTS`），通过数据库中的 120 秒租约在多个 Web worker 间共享限制。浏览器先请求通道再发送分片，服务端分片与完成接口也再次检查通道。无通道或磁盘不足时返回 429 和 `Retry-After`，前端使用有随机抖动的退避重试。离线或暂停后租约会自动释放；此机制不承诺严格先来先服务或准确等待时间。反向代理仍需限制请求大小并保留请求缓冲，否则慢速请求可能在到达应用前占用连接。单机上多个活动的总容量需要另行控制。

「正式提交 / 排队登记」允许将尚在上传的材料纳入提交清单。登记会锁定作品文字与已有上传任务清单，记录清单哈希和服务器时间；所需材料全部校验通过后自动正式提交。其他必填项仍必须齐全。取消上传、上传过期或校验失败不会成为成功提交。可取消排队提交后编辑，但截止后不能重新登记正式提交或更换文件。关闭页面不会在后台继续上传，需要保持页面打开或重新选择同一文件续传。

`cleanup_hackathon_uploads` 继续清理过期临时文件，但不再按七天删除上传记录；凭证随活动保留，便于后续技术核查。部署此次改动需运行 `python manage.py migrate hackathon`。

## ZIP 一级目录预览

已保存的 ZIP 附件提供一级目录预览。服务端仅读取有界的 ZIP 目录索引，不解压到磁盘、不执行内容，也不读取压缩文件正文。沿用上传的目录大小与条目数限制（目录不超过 4 MiB、最多 20000 个条目），最多返回 200 个一级条目，聚合子目录的文件数量和声明大小。仅队友、评委和主办方有权限查看；其他活动和未授权用户不能访问。文件名以文本显示，目录预览不证明压缩内容可运行或全部可解压。RAR / 7z 不在目前支持范围内。
