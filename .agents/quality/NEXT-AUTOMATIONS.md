# 后续自动化候选：按风险接入
这是一份待实施清单，不是当前网站仍存在这些缺陷的断言；先检查现有实现和测试。来源编号见 SOURCES.md。

| 背景或风险 | 可自动化的内容 | 技术与边界 |
|---|---|---|
| 域名、校园网、公网部署带来的不确定性 | DNS、TLS/重定向、静态资源、CSRF、登录 Cookie、OSS CORS、签名链接过期的上线烟测 | curl/浏览器 + Django 部署检查[S33]；从实际校园网和公网探测，SSH 隧道不能替代外部验证 |
| 截止前最后一次提交与网络中断 | 上传、重试、撤回、改队、再次提交的状态序列；服务端截止/时区/幂等断言 | pytest + Hypothesis stateful[S31]；预先确认业务规则，浏览器改时钟不代替服务端时间控制 |
| 团队成员不知道谁来决策业务规则 | 从任务卡收集待确认规则并生成决策表；代码/页面/FAQ一致性检查 | 单一任务卡为主源，Agent 汇总不代替主办方决定公平、截止或资源分配规则 |
| 活动当天网站失效后的人工接管 | 模拟备份恢复到隔离库，核对队伍/材料/提交回执；测试导出与兜底清单 | 复用既有脚本与恢复流程；备份文件存在不等于已验证可恢复，真实材料留在受限环境 |
| 最后时段集中上传 | 按已确认队伍数、材料分布和网络模型做受控负载，观察排队、错误率、完整性与恢复 | k6[S30]；浏览器 Agent 数量不等同并发用户容量；不对生产直接压测或凭空给出容量承诺 |
| 密钥、依赖与越权 | Gitleaks、pip-audit、既有授权负例、ZAP baseline | [S26–S28]；ZAP 被动扫描仍会请求站点，先限 staging 和范围；报告勿泄露选手信息 |
| 弱网、对象存储抖动 | TCP 断开/延迟/限速 + 前端反馈恢复 | Playwright 网络 mock[S36]用于确定性分支；Toxiproxy[S32]验证真实链路故障。响应延迟不等于真实带宽模拟 |
| 文档和演示逐渐过时 | Feature Map逐项对照源码与真实浏览器；自动生成截图版使用指南 | pstack create/maintain-verification-skill[S23–S24]；未跑的功能标 blocked/not_run，不能只更新文字宣布正确 |
| 自动化本身被弱化 | 新增忽略/跳过/黄金图更新/断言删除进入复看；用合成坏例验证新门禁确实失败 | 复用既有 reviewer 和 ledger；不用新增复杂审批流程 |

第一期优先前述两条核心旅程及与其相关的登录、持久化、权限、人工接管。其他任务单独排期；不要在活动前为自动化而重写已稳定的系统。
